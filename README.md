# 🛰️ SpaceWatch Bot v2 — بات رصد لحظه‌ای تصاویر و ویدیوهای فضایی

بات تلگرامی که **به‌محض انتشار**، جدیدترین تصاویر و ویدیوهای رسمی ماهواره‌های هواشناسی، خورشید و تلسکوپ‌های فضایی را از **۵۰ منبع رسمی** دریافت و برایت می‌فرستد — با **پوشش اختصاصی ایران و خاورمیانه** 🇮🇷

> نسخه ۲ یک بازنویسی کامل است: موتور موازی، تاخیر واقعی چند دقیقه‌ای، ویدیو، پنل امن، خودترمیمی و مصرف رم زیر ۳۰۰ مگابایت.

## ✨ چه چیزی نسبت به v1 عوض شد؟

| مشکل v1 | راه‌حل v2 |
|---|---|
| ❌ **هیچ عکسی از ایران/خاورمیانه نمی‌آمد** (لایه‌ی غلط `msg_fes` با bbox کل کره → ۷۸٪ عکس سیاه) | ✅ **۸ منبع اختصاصی** روی ایران و خاورمیانه: Meteosat-9 **IODC** (۴۵.۵°E، مستقیم بالای ایران) + Meteosat-12 **MTG-I1** — روز: رنگ طبیعی/واقعی، شب: مادون‌قرمز، Dust RGB، Airmass و GeoColour با **نور شهرها** |
| ❌ عکس‌های خیلی قدیمی ارسال می‌شد | ✅ زمان تصویربرداری از **متادیتای خودِ منبع** (slot دقیق WMS از GetCapabilities، نام فایل GOES/SUVI/LASCO، JSON ناسا) خوانده می‌شود؛ موارد قدیمی‌تر از ۳ روز فقط آرشیو می‌شوند و **ارسال نمی‌شوند** |
| ❌ فیدهای Hubble/Webb همه **404** بودند | ✅ API رسمی `d2d` ESA برای Hubble و Webb (تصویر + **ویدیو** 1080p) + NASA IOTD + APOD |
| ❌ منابع پشت‌سرهم (سریال) چک می‌شدند؛ هر ۳۰ ثانیه ۲.۶MB دوباره دانلود | ✅ **موازی** (۶ همزمان) + `ETag`/`If-Modified-Since` → فایل تغییرنکرده = یک 304 کوچک. یک دور کامل ۵۰ منبع: **~۲۵ ثانیه** ← فاصله چک همان ۳۰ ثانیه ولی چند برابر سریع‌تر و سبک‌تر |
| ❌ تشخیص «عکس ناقص» روی خورشید/فضای عمیق (پس‌زمینه سیاه) **اشتباه** می‌زد و ترمیم می‌کرد | ✅ بررسی **بایت‌سطح** (JPEG بریده) + تشخیص بصری فقط برای دیسک زمین و فقط باند **غیرسیاه**؛ خورشید و کهکشان دیگر ترمیم نمی‌شوند |
| ❌ پنل وب: **کادر تایپ هر ۴ ثانیه ریست می‌شد** (کل صفحه دوباره ساخته می‌شد) — توکن وارد نمی‌شد | ✅ صفحه یک بار رندر می‌شود؛ اعداد با `textContent` **در جای خود** آپدیت می‌شوند. دکمه‌ی 👁 نمایش توکن، 📋 پیست، **اعتبارسنجی زنده توکن** با getMe |
| ❌ لاگین فقط با آیدی عددی (عمومی!)، کوکی ساده، `/api/state` بدون لاگین همه‌چیز را لو می‌داد، CSRF نبود | ✅ **رمز پنل** (PBKDF2-SHA256)، سشن تصادفی هش‌شده، کوکی HttpOnly/SameSite، **CSRF token**، قفل ۱۵ دقیقه بعد ۶ تلاش ناموفق، هدرهای امنیتی (CSP، X-Frame-Options...)، توکن هرگز به مرورگر برنمی‌گردد (ماسک‌شده) |
| ❌ ویدیو نداشت | ✅ **۱۱ منبع ویدیو**: فیلم ۴۸ ساعته خورشید (SDO ۳ طول‌موج)، لوپ GOES (CONUS، مکزیک، اطلس، هاوایی)، کروناگراف SOHO C2/C3 (تبدیل MPEG→H.264 با ffmpeg)، ویدیوهای انتشاری Hubble/Webb |
| ❌ اگر بات می‌مرد کسی نمی‌فهمید | ✅ **Watchdog**: ری‌استارت موتور مرده/گیرکرده، ری‌استارت لایه تلگرام، نگهبان رم (soft 700MB / hard 900MB)، retention خودکار (۷ روز / ۳GB)، سرویس systemd با `MemoryMax=950M` و `Restart=always` |

## 🚀 نصب روی VPS (Ubuntu/Debian)

```bash
unzip spacewatch_v2.zip && cd spacewatch
chmod +x setup.sh
./setup.sh            # پیش‌نیازها + venv + ffmpeg + cloudflared + سرویس systemd
```

بعد برو به `http://IP-سرور:8080`:
1. توکن بات از [@BotFather](https://t.me/BotFather) (اعتبارسنجی زنده ✅)
2. آیدی عددی‌ات از [@userinfobot](https://t.me/userinfobot)
3. یک **رمز برای پنل** (حداقل ۸ کاراکتر)

```bash
sudo systemctl status spacewatch     # وضعیت
journalctl -u spacewatch -f          # لاگ زنده
sudo systemctl restart spacewatch    # ری‌استارت
```

اجرای دستی: `source venv/bin/activate && python main.py`

## 🏗️ معماری

```
main.py      ── asyncio loop: web(:8080) + file server(:8090) + Engine + BotManager + Watchdog
sources.py   ── رجیستری ۵۰ منبع + Engine (موازی، ETag/304، back-off نمایی، smart cadence)
repair.py    ── تشخیص بریدگی بایت‌سطح + inpainting OpenCV روی نسخه کوچک‌شده (رم پایین)
bot.py       ── هندلرها، ارسال عکس/ویدیو، reuse file_id، rate-limit، flood-guard
webui.py     ── پنل تک‌صفحه‌ای (patch-in-place)، PBKDF2، سشن، CSRF، lockout، CSP
database.py  ── SQLite WAL: config, users, media, source_state, sessions, events (+ مهاجرت از v1)
tunnel.py    ── cloudflared quick-tunnel برای فایل‌های +۴۹MB (نام تصادفی، انقضا ۲۴h)
i18n.py      ── ۱۰ زبان
test_run.py  ── ۷۰ تست آفلاین + `--live` یک دور واقعی روی همه منابع
```

**مسیر هر تصویر:** fetch (304 اگر تغییر نکرده) → sha1 dedup → اعتبارسنجی PIL → ذخیره → dark-skip (شبِ لایه‌های VIS) → تشخیص ناقص → ترمیم → پیش‌نمایش برای عکس‌های خیلی بزرگ → صف → ارسال به ادمین/کاربران (file_id یک بار آپلود، بقیه reuse)

**ذخیره‌سازی:** `data/bot.db` (SQLite WAL)، `data/images/`، `data/videos/`، `data/files/` (لینک‌های موقت)، `data/bot.log` (چرخشی ۳MB×۳)

**مصرف منابع (تست شده):** RSS در حالت idle ~۱۵۰MB، زیر بار ~۲۳۰MB • یک دور ۵۰ منبع ~۲۵ ثانیه • ffmpeg با `-threads 1` و `nice`.

## 🔒 امنیت (v2)
- رمز پنل با PBKDF2-SHA256 (۲۰۰k) + salt • سشن‌ها توکن تصادفی ۳۲ بایت، هش‌شده در DB، انقضا ۱۴ روز
- کوکی `HttpOnly; SameSite=Strict` • CSRF header برای همه POSTها • قفل IP بعد ۶ تلاش/۱۵ دقیقه + تأخیر ۳۰۰ms
- CSP، X-Frame-Options DENY، nosniff، no-store • `/api/state` بدون لاگین فقط `{configured, admin}`
- توکن بات هرگز به کلاینت برنمی‌گردد • بررسی توکن (getMe) فقط قبل از setup یا با لاگین (جلوگیری از oracle)
- فایل‌سرور: basename + whitelist کاراکتر (بدون path traversal)، نام تصادفی، فقط localhost
- تلگرام: بررسی سخت ادمین، regex دقیق callback، flood guard ۶ دستور/۱۰ ثانیه، حداکثر حجم دانلود
- systemd: `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=full`, `MemoryMax=950M`
